## Review corrections

- Stop removes the foreground position observer before native/SQLite awaits and remains reachable with unknown or broken storage.
- Cold JS startup unregisters the stored location task before reading SQLite, then pauses a previously active diagnostic.
- A persisted Expo task registration is displayed as registration, not live foreground service health.
- Start tests user-initiated foreground service with While Using permission; Always permission is optional and separately explained.
- Marker observations carry a timestamp and are cleared on expiry, permission/service loss, pause and stop.
- A pending cancelled Start retains an operation slot until cleanup finishes, so it cannot stop a newer accepted Start. Emergency Stop can execute while Start is pending.

## Unaccepted gates

No phone was connected. Installation/launch/UI rendering, actual notification, foreground service liveness, Stop during OS/storage failure, foreground/approximate/denied permission, GPS off, 30 minute walk/20 minutes screen off, battery, real process death and SQLite restart durability were not tested.

Expo may restore persisted location consumers **before JS cleanup**. That is an unresolved privacy gate; the diagnostic APK must not be promoted to an accepted beta. The next scoped candidate is a non-persistent Kotlin foreground adapter with in-process consent, `START_NOT_STICKY`, a native notification Stop action and no persisted auto-resume.

A second concrete privacy finding comes from the installed primary SDK sources: `expo-location@58.0.18` LocationTaskConsumer.kt packages full locations as `PersistableBundle` and schedules Android jobs; `expo-task-manager@58.0.12` TaskManagerUtils.java creates those jobs with `JobInfo.Builder.setPersisted(true)`. Our SQLite does not store coordinates, but Expo/Android's job queue can persist them. UI/README explicitly disclose that limitation. App-owned coordinate persistence, retention and queue cleanup are not accepted; the planned native replacement must remove that path. No source in the diagnostic promises that precise position exists only in RAM.

Device TTS discovery/playback is implemented, but actual voice availability, Kazakh quality, offline TTS and background audio remain untested. A matching OS voice does not establish a license to save the generated audio.
