# Работа над AstGeo на двух Windows-ноутбуках

Исходники приложения находятся в этом репозитории. Продуктовый scope описан в [FOCUSED-RELEASE.md](FOCUSED-RELEASE.md), фактическая версия — в [IMPLEMENTATION-STATUS.md](IMPLEMENTATION-STATUS.md).

## Ветки и проверка

- Ноутбук владельца: `codex/backend`; ноутбук друга: `codex/frontend`. Новые задачи могут использовать отдельные `codex/<task>` и Pull Request.
- Работайте в отдельных клонах/worktrees. Между задачами из чистой рабочей папки выполните fetch и merge `origin/main` в свою ветку.
- Отправляйте только законченные изменения обычным push. Общие контракты и зависимости согласуйте до правок. Не используйте force push и не удаляйте чужую работу.
- Для автоматических Node-проверок нужны Windows, Node.js 24 и npm в PATH. Определения находятся в `.codex/integration-checks.json`: сначала установка зависимостей обоих lockfile с отключёнными lifecycle scripts, затем strict Node build, Node runtime checks и mobile TypeScript.
- Эти проверки не собирают Android APK и не заменяют проверки телефона/поля. Полный локальный набор описан в [README приложения](../apps/mobile/README.md) и `scripts/verify-local.ps1`.

## Фоновый интегратор

`tools/Sync-Integration.ps1` запускается из отдельного служебного клона и получает `origin/main`, `origin/codex/backend` и `origin/codex/frontend`. Он объединяет ещё не включённые коммиты в detached worktree, выполняет `.codex/integration-checks.json` и публикует обычным push. Неподдержанные новые ветки публикуются через Pull Request.

При конфликте или неуспехе проверок публикация останавливается; проблемный worktree сохраняется. Скрипт не меняет рабочие папки разработчиков. Параметры `-DryRun` и `-Retry` предназначены для диагностики. Защита main не обходится: при её наличии используется Pull Request.

Предыдущие ветки backend/frontend были служебным каркасом. Их история сохранена, а включённые коммиты остаются предками main: интегратор не откатывает приложение к старому каркасу.

Расписание в Codex и SSH/Windows-MCP настраиваются отдельно на конкретных компьютерах. Не публикуйте ключи, токены, настройки с секретами, node_modules или APK в Git. Покупки, платные API и платная облачная сборка запрещены.
