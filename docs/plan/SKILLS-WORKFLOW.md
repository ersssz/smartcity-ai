# Как применять установленные навыки

Дата: 20 октября 2026. Одинаковая версия набора Matt Pocock установлена и сверена на обоих ноутбуках: commit `5beb35b040e3de97e54fa9e386d7e42d15c295c2`, 38 навыков, 103 файла. Переносимый список и hashes находятся в [skills-lock.json](skills-lock.json). Это проверка именно этого набора; другие навыки, модели и настройки двух Codex могут различаться.

## Планирование

`grill-me` является входом в `grilling`: решения разбираются по зависимостям, факты исследуются агентами, на доступные для решения вопросы пользователь отвечает раундами. В этом проекте Q1–Q8 подтверждены пользователем; последующее прямое поручение автономно завершить план передало оставшиеся решения главному Codex. Поэтому интервью завершено, а выбранные параметры и технические неизвестные явно записаны в DECISIONS и gates. Это применение полномочий пользователя, а не предположение, что отсутствие ответа означает согласие.

| Работа | Навыки | Проверяемый результат |
|---|---|---|
| Уточнить изменение цели | `grill-me` → `grilling` | Решения и зависимости; вопросы только о действительно неизвестном выборе пользователя |
| Проверить возможности API/данных | `research` | Первичные источники с датой, выводы, ограничения и отдельные ещё не выполненные эксперименты |
| Зафиксировать продукт | `to-spec` | Problem, scope, истории, приёмка и пределы обещаний в PRODUCT-SPEC |
| Спроектировать границы | `codebase-design`, `domain-modeling` | Небольшой Interface глубокого модуля, единый глоссарий, объяснение значимых решений |
| Разбить работу | `to-tickets` | Один файл на проверяемый результат, прямые блокировки, владелец, US/AT и доказательство готовности |
| Подготовить передачу | `writing-for-agents`, `handoff` | Краткий пакет задачи с указателями на нормативные документы и актуальный SHA |

## Реализация после начала соответствующей фазы

Для принятого билета агент читает его, подходящие навыки и нужные разделы спецификации. Загрузка всех 38 навыков в каждую задачу расходует контекст и создаёт ненужные процедуры. Применение навыка не делает его команды независимым разрешением на внешнюю публикацию или изменение настроек.

| Ситуация | Навыки | Граница применения |
|---|---|---|
| Реализация вертикального результата | `implement`, при необходимости `tdd` | Поведенческие проверки инвариантов: бюджет пути, состояние сессии, идемпотентность, права профиля. Для простого текста/стиля лишний тест не создаётся |
| Воспроизводимый сбой | `diagnosing-bugs` | Наблюдаемая ошибка → гипотеза → ограниченный эксперимент → исправление → проверка исходного сценария |
| Независимая приёмка | `code-review` | Отдельные Standards и Spec, фиксированные base/head SHA, затем проверка интегрированного пути |
| Описание изменения в PR | `pr` | Проблема, итоговое поведение, реальные проверки и существенные ограничения |
| Настройка только человеком | `wizard` | Только действия, действительно требующие владельца аккаунта/устройства; не перекладывать доступные агенту действия |
| Неопределённость интерфейса | `prototype` | Отдельный ограниченный эксперимент с вопросом и выводом; его существование не считается готовностью продукта |

## Особенности Codex и двух ноутбуков

Шаблоны исходного репозитория могут упоминать другой агентный клиент, bash, hooks или способы запуска субагентов. Используются доступные возможности Codex и PowerShell, без автоматической установки чужих hooks. `git-guardrails-claude-code` и `claude-handoff` не считаются защитами или транспортом Codex; экспериментальные навыки не входят в обязательный цикл проекта. `setup-pre-commit` рассматривается только после появления реальных команд и правил репозитория.

Компьютерное управление полезно для настройки и визуального наблюдения. Оно не заменяет воспроизводимые проверки программы. Playwright не является обязательной зависимостью Android-приложения; для веб-страницы публичной коллекции средство проверки выбирается по задаче. Android проверяется сборкой, инструментальными сценариями и реальным телефоном; Windows-MCP второго ноутбука сам по себе не доказывает работу телефона или полевую прогулку.

Контекст двух Codex передаётся через документы, общий контракт, отдельные ветки и принятые commits согласно [TEAM-WORKFLOW](TEAM-WORKFLOW.md). Установленные skills помогают выполнять этот процесс; они не предоставляют общую память чатов и не запускают второго исполнителя автоматически.

Версия навыков обновляется отдельным осознанным изменением: сохранить прежний lock, проверить изменившиеся инструкции, обновить обе установки и повторно сравнить hashes. Автоматическое обновление посреди задачи нарушило бы воспроизводимость.
