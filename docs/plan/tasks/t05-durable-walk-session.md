## Что получает пользователь

Из готового пакета пользователь начинает прогулку, видит текущую остановку, после закрытия приложения продолжает с того же места и получает единственный итог.

## Scope и самостоятельность

WalkSession: экран прохождения, локальное хранение и события. Независимо демонстрируется на явно тестовом WalkBundle; реальный GPS ещё не засчитывается.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Start → active → paused → resumed → completed/cancelled имеет явные допустимые переходы. В приложении одновременно одна активная прогулка.
- [ ] Локально транзакционно сохраняются bundle revision, событие и рассчитанное состояние; выгрузка процесса между записью/отрисовкой не теряет подтверждённый прогресс.
- [ ] Повторная доставка одного события, завершения или нажатия кнопки не создаёт дубль итога/достижения.
- [ ] После перезапуска видны последний подтверждённый шаг и точный статус сессии; пользователь может продолжить или явно завершить.
- [ ] ManualVisitMark хранится отдельно от Arrival и помечен как ручной. Тестовое событие не выдаётся за обнаружение GPS.
- [ ] Реальный bundle T04 подключается без изменения Interface; самостоятельная приёмка T05 не ждёт T04.

## Ошибки и пограничные случаи

- Повреждение/несовместимость локального состояния: безопасный экран восстановления, исходная запись сохраняется для диагностики без GPS-утечки.
- Повторный запуск другого bundle: явный выбор пользователя; активная сессия не перезаписывается.

## Доказательство готовности

- Запись start → manual mark → process kill → resume → complete → повтор события.
- Проверки переходов/идемпотентности через Interface и migration fixture.
- Точный SHA и отметка, где использовался fixture, а где реальный bundle.
