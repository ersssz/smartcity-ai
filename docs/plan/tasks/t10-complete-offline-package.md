**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.

## Что получает пользователь

После явного завершения загрузки пользователь видит сохранённую карту и маршрут, читает/слушает материалы, проходит задания и сохраняет прогресс без интернета.

## Scope и самостоятельность

WalkSession offline asset manifest, разрешённая подложка, локальные материалы и атомарная загрузка.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Offline-ready означает проверенные карта/геометрия, остановки, RU/KK/EN-материалы, заранее доступное аудио и задания конкретного пакета; один сохранённый GeoJSON не засчитывается как offline-карта.
- [ ] До загрузки показаны размер и состав; нехватка места, отмена, частичная загрузка и неверный hash не создают ложный ready.
- [ ] Готовность привязана к конкретной revision/hash/manifest; смена пакета требует повторной проверки состава. Доступные файлы с совпадающими hashes используются повторно, но готовность прежней revision не переносится целиком.
- [ ] В airplane mode работают карта в заявленной зоне, текущая остановка, текст, аудио, задания и транзакционный прогресс; после выгрузки процесса сессия восстанавливается.
- [ ] Перестроение нового пешеходного графа offline отсутствует в v1. При отклонении показываются сохранённая линия, позиция/статус и предложение вернуться или дождаться сети; новый путь не изображается как рассчитанный.
- [ ] Свежая погода, изменившееся расписание и новые AI-ответы offline не обещаются; видны возраст сохранённых сведений и режим без сети.
- [ ] Удаление пакета с активной сессией требует явного решения; кэш удаляется без удаления коллекции и подтверждённого прогресса.

## Ошибки и пограничные случаи

- Пакет повреждён после загрузки: назвать недоступный материал, сохранить состояние и предложить восстановление при сети.
- Пользователь вышел за пределы карты: показать границу покрытия и доступную сохранённую геометрию.

## Доказательство готовности

- Полная запись airplane-mode: карта → аудио → задание → process kill → resume → итог.
- Матрица asset manifest с hashes и лицензиями.
- Проверки места/обрыва/повреждения/отклонения без фиктивного offline-reroute.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
