## Что получает пользователь

Пользователь задаёт старт и время, получает одну доказуемо выполнимую прогулку по реальному району, открывает её карту и объяснение выбора.

## Scope и самостоятельность

CityEvidence → WalkPlanner → Android preview. Включает минимальный реальный импорт и один законченный путь; не требует завершения WalkSession.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Реальный автоматизированный импорт из T02 воспроизводится идемпотентно; базовый городской каталог имеет административный охват и честный отчёт фактического покрытия. UI показывает происхождение и дату критических фактов; глубокие guided-пакеты ограничены подтверждёнными зонами.
- [ ] Ручной старт работает при отказе геолокации. Возврат к старту выбран по умолчанию; пользователь может явно выбрать последнюю остановку или заданный конец.
- [ ] Предложение содержит реальную пешую геометрию, порядок мест, переходы, посещения, выбранное окончание и резерв в общем временном бюджете.
- [ ] Реальная GPS-точка старта/возврата и выбранный конец обработаны законным Adapter из T02. Публичный anchor, прямая линия и вымышленный connector не подменяют несчитанный участок; явный выбор другого старта/конца сохраняется в WalkRequest и виден до принятия.
- [ ] Запуск запроса → фактический backend → валидный WalkBundle → карта и список остановок работают в APK; серверные ключи отсутствуют в клиенте.
- [ ] Есть понятные состояния загрузки, отмены, отсутствия выполнимого результата и недоступности сети. Приложение не создаёт вымышленный POI для заполнения ответа.
- [ ] В доказательстве отмечены проверенные район, источники и дата. Тестовый Adapter явно отличим от реального.

## Ошибки и пограничные случаи

- Недостаточные данные для старта/района или отсутствует путь: объяснить ограничение и предложить подтверждённый район/изменение условий; не подменять запрос скрытно.
- Неизвестное критическое расписание/проходимость: исключить зависящее от него обещание либо заменить остановку подтверждённой.

## Доказательство готовности

- Видео запроса до карты реальной прогулки и сохранённый обезличенный запрос/ответ.
- Контрольный пересчёт временного бюджета и проверка связей источников.
- Проверки отсутствующего пути, отказа GPS и серверной ошибки.
