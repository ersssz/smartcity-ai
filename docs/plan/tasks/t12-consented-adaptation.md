## Что получает пользователь

Из активной прогулки пользователь просит изменить план и получает подтверждённую альтернативу в оставшемся времени; приложение сохраняет уже пройденное.

## Scope и самостоятельность

WalkPlanner online replan → предложение изменений → подтверждение → новая bundle revision и продолжение WalkSession.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Сценарий 80 минут «необычное и кофе» → прохождение → «замёрз, хочу внутрь» учитывает фактически оставшееся время, текущую точку и выбранное окончание.
- [ ] Предлагаемый вход внутрь имеет подтверждённые критические условия; отсутствие сведений приводит к альтернативе или честному отказу, а не обещанию открытого кафе/музея.
- [ ] Изменение состава остановок или существенного времени показано сравнением и применяется только после явного согласия пользователя.
- [ ] Новая immutable revision сохраняет подтверждённые события/открытия и не повторяет награды; отклонённое предложение не меняет текущий пакет.
- [ ] После принятия адаптации готовность offline проверяется для новой revision/hash/manifest. При новой области карты или аудио и обрыве скачивания UI показывает недостающие ресурсы; готовность старого пакета не наследуется. Старые доступные материалы и прогресс сохраняются.
- [ ] Timeout, отмена и повторная отправка не создают несколько активных сессий; запрос/ответ привязан к актуальной revision.
- [ ] При отсутствии сети остаётся сохранённая прогулка. UI не обещает offline-перестроение и предлагает понятное действие.
- [ ] При онлайн-отклонении допустима автоматическая коррекция только перехода к тому же согласованному плану, если сохраняются stops/theme/end rule и нормативная граница времени. Смена остановок/темы/существенное удлинение требует согласия; offline этот механизм недоступен.

## Ошибки и пограничные случаи

- Ответ пришёл для устаревшей revision: не применять, предложить повтор для текущего состояния.
- Нет выполнимой внутренней остановки: назвать ограничение и предложить завершение/сокращение с сохранением прогресса.

## Доказательство готовности

- Видео главного сценария с подтверждением и без подтверждения.
- Трасса бюджета до/после и ссылки на сведения о доступности.
- Проверки устаревшего ответа, offline, повторного запроса и сохранённых наград.
