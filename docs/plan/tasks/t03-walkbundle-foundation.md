## Что получает пользователь

Оба Codex собирают одинаковую основу, а пользователь открывает версионированный пакет прогулки и видит карту, остановки, материалы и возможность начать сессию.

## Scope и самостоятельность

WalkBundle v1, Native foundation и единый pipeline сборки. Root — владелец общих Interface, миграций, зависимостей и lockfile до явной передачи владения.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] WalkBundle v1 нормативно описывает request/end rule, immutable revision, порядок остановок, наружные arrival anchors, пешие legs/GeoJSON, длительности/резерв, factRefs, снимки контекста, RU/KK/EN-контент, questIds, аудио и offline asset manifest.
- [ ] Прогресс и посещения находятся вне immutable bundle. Валидация различает неподдерживаемую версию, повреждённые assets, отсутствующие критические поля и корректное неизвестное значение.
- [ ] Есть один явно тестовый, лицензированно допустимый fixture-пакет и его валидатор. Внутренний preview показывает все остановки, геометрию, язык и статус готовности offline-материалов.
- [ ] Одинаковый lockfile и спецификация дают воспроизводимую сборку на обоих ноутбуках; локальные clone независимы. Не предполагается автоматически общая история чатов.
- [ ] Согласованы небольшие Interface CityEvidence, WalkPlanner, WalkSession и PublicCollection; адаптер fixture и реальный Adapter разделены так, чтобы planner и session могли разрабатываться параллельно.
- [ ] Подготовлены минимальные инструкции агента, среда без ключей в Git и проверки контракта/типов/сборки. Включены тесты невалидного bundle и отсутствующего asset.

## Ошибки и пограничные случаи

- Schema version неизвестна: показать совместимое сообщение и сохранить исходный пакет, не теряя прогресс.
- Asset не совпал по hash: пакет не становится offline-ready, загрузка может быть повторена.

## Доказательство готовности

- SHA базового коммита, checksum fixture и схема/валидатор WalkBundle v1.
- Сборки и краткий preview на обоих ноутбуках/доступных Android.
- Контрактные проверки с положительными и отрицательными примерами.
