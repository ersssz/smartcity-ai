# T21: Продолжить продукт при сбоях backend и восстановить его безопасно

**Владелец:** Root  
**Blocked by:** T19 — Провести пилот, собрать FIELD-PASS и измерить пользу  
**Статус:** blocked  
**Этап:** G3 — эксплуатационная устойчивость  
**Спецификация:** [PRODUCT-SPEC](../PRODUCT-SPEC.md) — US-15, US-24–26, US-31–32, US-34; AT-06, AT-14–17, AT-19.  
**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.  
**Оценка:** 1–2 рабочих дня; измеренный прогноз уточняется после baseline.  
**Base SHA / ветка:** назначает Root при старте; ветка codex/t21-operational-recovery. Сейчас кода/репозитория нет.

## Что получает пользователь

Сохранённые прогулки переживают недоступность backend, а команда восстанавливает актуальные данные и публикации без утечки секретов и необратимого расхода.

## Scope и самостоятельность

Пользовательский outage/recovery сценарий Workers + Supabase + Android, данные, публикации и минимальная наблюдаемость.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Проверены outage backend, истечение кредитов/лимита, неуспешное обновление каталога и деградация внешнего routing; сохранённая прогулка продолжает работать в пределах offline-обещания.
- [ ] Есть фактическая backup/restore-проверка минимальных серверных данных; токены/секреты не попадают в публичные backup-артефакты.
- [ ] Ошибки, задержки, quota и качество источников наблюдаемы без обычного хранения точного GPS; определены сроки удаления диагностических данных.
- [ ] Read-time expiry публичного профиля действует даже при задержке cron. Backup/restore и rollback никогда не возобновляют чтение revoked/rotated URL; отзыв необратим для старой ссылки. Expired профиль продлевается только явным действием владельца по нормативному правилу, а новая публикация после revoke получает новый URL.
- [ ] Доступность при $0 описана фактическими лимитами и режимом закрытого пилота; непрерывная публичная работа не обещается, пока её ресурс не доказан.
- [ ] Rollback новой версии схемы/каталога/приложения безопасен либо явно указан необратимый переход и проверенная процедура; ручные шаги документированы.

## Ошибки и пограничные случаи

- Бэкап устарел/повреждён: восстановление не считается успешным по самому наличию файла.
- Неустранимое ресурсное ограничение: уменьшить доступную нагрузку и честно ограничить пилот, сохранив данные.

## Доказательство готовности

- Запись outage → offline continuation → backend restore.
- Фактический restore report с версиями и checksums без секретов.
- Минимальный runbook, лимиты и проверенный rollback/upgrade-сценарий.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
