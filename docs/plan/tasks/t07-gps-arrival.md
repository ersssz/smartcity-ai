## Что получает пользователь

Во время активной прогулки пользователь получает одно уведомление о первом подтверждённом приложением прибытии рядом с историческим местом; ручная отметка остаётся отдельной.

## Scope и самостоятельность

WalkSession + foreground location + Arrival. Значения радиуса, точности, dwell и антидребезга берутся из нормативного PRODUCT-SPEC/WalkBundle v1, а не вводятся локально.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Arrival означает нахождение рядом с наружным anchor; UI не утверждает вход в музей, покупку билета или физическое посещение помещения.
- [ ] Вход в радиус с подходящей точностью и выдержкой создаёт Arrival и первое уведомление ровно один раз. Граница, дрейф, низкая точность, старое событие, повтор и выход/возврат проверены.
- [ ] При запрещённых системных уведомлениях Arrival и открытие сохраняются, видны внутри приложения и не повторяются после выдачи разрешения; просьба разрешения имеет контекст.
- [ ] ManualVisitMark не превращается в GPS-подтверждение и не получает соответствующую отметку; оба вида сохраняются различимо в коллекции/истории.
- [ ] Автоматическое распознавание проходит при погашенном экране в активной сессии; пауза/завершение останавливают слежение.
- [ ] При потере разрешения/GPS пользователь видит деградацию и может продолжить с ручными отметками; восстановление разрешения не создаёт ложную серию Arrival.
- [ ] Симуляция/GPS-replay и фактическая прогулка, если проведена, записаны отдельно. Техническое закрытие T07 не доказывает полевое качество; обещание проверенного сопровождения требует FIELD-PASS T19.

## Ошибки и пограничные случаи

- Два соседних anchor: применить нормативное правило выбора/неоднозначности, не присуждать всё сразу.
- Пропуск фоновых событий: сохранить доступный прогресс и показать состояние, не обещать непрерывное распознавание.

## Доказательство готовности

- Журнал граничных сценариев и тесты через Interface.
- Screen-off видеопроверка и обезличенные интервалы обновлений.
- Если доступно — полевое свидетельство входа/выхода; без него T07 может закрыть техническую логику с честной маркировкой GPS-replay. FIELD-PASS остаётся отдельным gate T19 перед внешним T22.
