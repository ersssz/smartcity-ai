# T20: Получить новую прогулку с учётом уже открытого

**Владелец:** Root  
**Blocked by:** T19 — Провести пилот, собрать FIELD-PASS и измерить пользу  
**Статус:** blocked  
**Этап:** G3 — повторная ценность  
**Спецификация:** [PRODUCT-SPEC](../PRODUCT-SPEC.md) — US-36–37; AT-01, AT-20; метрики повторного использования.  
**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.  
**Оценка:** 1–2 рабочих дня; измеренный прогноз уточняется после baseline.  
**Base SHA / ветка:** назначает Root при старте; ветка codex/t20-repeat-value. Сейчас кода/репозитория нет.

## Что получает пользователь

На основе фактических наблюдений пилота возвращающийся пользователь получает улучшенный повод выйти снова; это углубляет уже работающий в M2 базовый выбор следующей главы.

## Scope и самостоятельность

Улучшение локальной Collection → privacy-preserving WalkRequest preferences → WalkPlanner → новой прогулки. Базовая повторная ценность не отложена: её реализуют T11 и проверяют T18.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Пользователь явно выбирает учитывать свои открытия; передаваемый минимум данных описан, приватный GPS-трек не требуется.
- [ ] Планировщик предпочитает непройденные подходящие главы/места при наличии выполнимого выбора; повтор может быть предложен с понятной причиной.
- [ ] При отсутствии новых проверенных вариантов приложение честно сообщает это и предлагает другую тему/район/время вместо выдуманных POI.
- [ ] Существующие достижения сохраняются, новая прогулка имеет отдельную сессию; повтор прохождения не дублирует уникальные открытия.
- [ ] Улучшение выбрано по наблюдениям T18; полное изменение профиля/аккаунтная система не добавляются без необходимости.

## Ошибки и пограничные случаи

- История удалена или отсутствует: обычный путь работает без персонализации.
- Слишком узкие ограничения: объяснимое сокращение выдачи, возможность отключить учёт истории.

## Доказательство готовности

- Сравнение выдачи для нового и возвращающегося пользователя на одном каталоге.
- Проверки приватности payload и уникальности открытий.
- Повторный пилотный сценарий с фактической оценкой полезности.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
