## Что получает пользователь

Пользователь понимает, почему предложены эти места, и получает связанный с прогулкой ответ, основанный на найденных карточках, с честным признанием недостаточных сведений.

## Scope и самостоятельность

CityEvidence retrieval → grounded generation → карточка источников в Android. AI работает через сервер; права источников сохраняются.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Реальный retrieval использует импортированные POIEvidence; сохраняется связь найденного фрагмента, использованного факта и отображаемого утверждения.
- [ ] Подготовлен фиксированный набор минимум 20 вопросов: известные факты, недостаточные данные, конфликт источников, неподходящее расписание и попытка навязать факт из текста источника.
- [ ] Для всех критических утверждений тестового набора есть источник; выдуманные адреса, режимы работы, стоимость и гарантии доступа не проходят приёмку.
- [ ] Недостаточные сведения приводят к ограниченному ответу/подтверждённой альтернативе. Текст источника обрабатывается как данные, а не инструкции.
- [ ] Тексты RU/KK/EN используют один набор идентификаторов фактов; перевод не добавляет новых фактов. Художественная часть явно обозначается.
- [ ] Исчерпание AI-квоты/timeout оставляет доступными проверенные карточки и уже сохранённую прогулку; доступ к платному API по умолчанию выключен.

## Ошибки и пограничные случаи

- Retrieval пуст: нет искусственного заполнения источниками; UI предлагает изменить вопрос или открыть фактическую карточку.
- Модель ссылается на отсутствующий factRef: ответ не публикуется как проверенный, применяется безопасный fallback.
