## Что получает пользователь

Добровольцы проходят продукт без подсказок разработчика; команда получает наблюдения о пользе и отдельные реальные доказательства проходимости/GPS для заявленных районов.

## Scope и самостоятельность

Пилотный пользовательский путь, добровольная минимальная обратная связь и разбор. Внешние приглашения отправляются людьми или только при отдельном разрешении на сообщения.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Размер выборки, сегменты жителей/туристов и целевые показатели берутся из PRODUCT-SPEC/DECISIONS A06. Фактическое число добровольцев и условия указаны отдельно; повторения разработчика не заменяют независимых участников.
- [ ] Измеряются старт/выбор/завершение, понятность следующего действия, причины отказа и запрос на повторную прогулку; точный GPS-трек не нужен для обычной аналитики.
- [ ] Наблюдения отделены от мнений и самоотчёта; нельзя утверждать retention по намерению пользователя вернуться.
- [ ] Собраны баги с воспроизведением/версиями и три приоритетных улучшения по наблюдаемому влиянию.
- [ ] Обратная связь доступна на RU/KK/EN либо сбор языковой выборки честно ограничен; согласие и удаление сведений работают.
- [ ] FIELD-PASS выполнен по EXECUTION: реальные полные сюжетные прогулки во всех трёх глубоких зонах и требуемая проверка второго Android, наружных anchors/переходов, погашенного экрана, потери сети, остановки и восстановления. При отсутствии части доказательств поле остаётся FAIL, даже если техническая бета и интервью успешны.

## Ошибки и пограничные случаи

- Мало добровольцев/разные условия: описать ограничение выборки, не рисовать статистическую значимость.
- Неудобный/опасный участок: оперативно выключить соответствующую рекомендацию до проверки.

## Доказательство готовности

- Обезличенная таблица фактических прохождений и согласия.
- Список наблюдений, приоритетов и воспроизводимых дефектов.
- Решение о готовности расширять пилот с аргументами.
- Отдельный FIELD-PASS report с зонами, устройствами, погодными условиями, датами и пределами доказательств.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS.
