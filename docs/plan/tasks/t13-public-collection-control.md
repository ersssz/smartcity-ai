# T13: Опубликовать выбранную коллекцию и управлять ссылкой

**Владелец:** Root  
**Blocked by:** T11 — Открыть главу, выполнить квест и сохранить коллекцию  
**Статус:** blocked  
**Этап:** G1 — публичный профиль без регистрации  
**Спецификация:** [PRODUCT-SPEC](../PRODUCT-SPEC.md) — US-28–33; AT-12, AT-16–17.  
**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.

**Base SHA / ветка:** назначает Root при старте; ветка codex/t13-public-collection-control. Сейчас кода/репозитория нет.

## Что получает пользователь

Пользователь явно публикует выбранные открытия под псевдонимом, затем обновляет, отключает или заменяет постоянную ссылку; личный ход прогулок остаётся закрытым.

## Scope и самостоятельность

PublicCollection: Android opt-in → Workers → Supabase → публичная страница и capability-based управление.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Публикация выключена по умолчанию; до отправки показан точный preview псевдонима, значков и открытий и требуется явное действие.
- [ ] Текущая позиция, GPS-трек и точные даты посещений не входят в публичный payload, HTML, metadata, logs и аналитические события.
- [ ] Read-token и device admin capability раздельны; сервер хранит необходимые hashes и не выводит секрет управления в страницу/логи. Публичная ссылка не даёт права редактировать.
- [ ] Обновления атомарны и имеют revision; повтор PublishOperation не дублирует профиль, старый ответ не перезаписывает новое состояние.
- [ ] Из приложения работают revoke и rotate; старая ссылка становится недоступной. Expiry/revoke немедленно запрещают чтение HTML/JSON и кеша по нормативному TTL; active payload очищается по DECISIONS A05. Истечение/очистка и retention резервных копий различаются.
- [ ] После потери телефона/admin capability восстановления в бете нет; это явно объяснено до публикации. Отмена/отключение не удаляет локальную коллекцию.
- [ ] Только явный publish/update продлевает срок; обычное чтение, GPS и фоновая активность этого не делают. Вид публичной страницы RU/kk/EN согласован с опубликованным выбором языка.
- [ ] Expiry и revoke различаются: истёкшую публикацию можно явно продлить/опубликовать повторно с сохранённым правом управления по нормативному правилу; отозванный или заменённый URL никогда не становится доступным снова. После revoke новая публикация получает новый URL; restore старой БД не воскрешает отозванную ссылку.

## Ошибки и пограничные случаи

- Сеть оборвалась после отправки: повтор с тем же operation id восстанавливает исход операции, не создаёт новую публикацию.
- Чужой/истёкший token, параллельные update/revoke: отказ без утечки и корректный приоритет отзыва.

## Доказательство готовности

- Видео opt-in → view → update → revoke → rotate с очищенными секретами.
- Контрактные тесты capability, expiry/явного продления, неизменяемости revoke/rotate, stale revision, идемпотентности и запрета восстановления revoked URL.
- Сравнение публичного payload/страницы с перечнем исключённых личных данных.
