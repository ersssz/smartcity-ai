# T17: Выпустить обязательное содержание M2 в трёх глубоких зонах

**Владелец:** Друг  
**Blocked by:** T08 — Выбрать из 1–3 выполнимых прогулок с учётом контекста; T10 — Сохранить прогулку и продолжить её полностью без сети; T14 — Выпустить первую содержательную прогулку на трёх языках  
**Статус:** blocked  
**Этап:** G1 — обязательное содержание M2 до полной беты  
**Спецификация:** [PRODUCT-SPEC](../PRODUCT-SPEC.md) — US-04, US-19–25, US-35–37; AT-01–04, AT-10–14, AT-20.  
**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.  
**Оценка:** 2–3 рабочих дня наполнения/проверки на район; зависит от доступа к редакции и полю; измеренный прогноз уточняется после baseline.  
**Base SHA / ветка:** назначает Root при старте; ветка codex/t17-district-coverage. Сейчас кода/репозитория нет.

## Что получает пользователь

Пользователь получает содержательные прогулки EXPO, района Байтерека и старого центра с одинаковым уровнем фактической опоры, трёхъязычного рассказа, заданий и offline-пакета; первая бета не ограничивается одним техническим маршрутом.

## Scope и самостоятельность

CityEvidence ingestion → проверка маршрутов → публикация глав/квестов → Android bundle. Точный минимум POI/цепочек/глав/достижений находится только в PRODUCT-SPEC (M2) и DECISIONS A01; T02 лишь проверяет его достижимость.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Выполнен весь нормативный редакционный минимум M2 из PRODUCT-SPEC/DECISIONS A01 по трём названным зонам; числа сверены при приёмке, а не выдуманы по наличию объектов на карте.
- [ ] Для каждой зоны опубликованы проверенные карточки/наружные anchors, пешие переходы, связная глава/цепочка, задания и открытия на RU/kk/EN с core offline audio.
- [ ] Автоматический базовый городской каталог и обогащённый редакционный корпус различаются в отчёте. Полнота административного города не доказывается числом подробных POI.
- [ ] Импорт и редакционные версии воспроизводимы; критические конфликты, устаревшие факты и отозванные материалы не попадают в новые пакеты.
- [ ] Для каждого выпускаемого пакета проверены лицензии/атрибуция, factRefs, аудио и offline asset manifest. Пакет доступен в реальном Android-пути.
- [ ] Полевые свидетельства и компетентная языковая проверка записаны раздельно. Отсутствие поля не блокирует M2-TECH с маркировкой исследовательского режима, но не становится обещанием проходимости: FIELD-PASS собирается T19 и обязателен перед внешним T22.

## Ошибки и пограничные случаи

- Недостаточно контента/проходимости в зоне: M2-gate не закрывается; прогноз меняется, район не включается формально ради числа.
- Изменились расписание/права источника: приостановить зависящие предложения и обновить доказательства.

## Доказательство готовности

- Матрица M2 из SPEC: плановый минимум → фактически опубликованные версии по трём зонам.
- Редакционные/языковые свидетельства, источники и ограничения. Полевые данные — только при наличии, не условие M2-TECH; обязательный FIELD-PASS собирает T19.
- Видео открытия представительного bundle каждой зоны, включая offline-материалы.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
