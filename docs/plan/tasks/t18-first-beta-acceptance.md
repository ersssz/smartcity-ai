## Что получает пользователь

Взрослый участник закрытого исследования получает сборку со всеми обязательными возможностями и контентом. Техническая приёмка ещё не означает полевую надёжность или готовность внешнего продукта.

## Scope и самостоятельность

Независимая техническая интеграционная приёмка M2-TECH. Поле и полезность проверяются T19; их отсутствие не создаёт цикл выдачи исследовательской сборки. Эта задача не заменяет разработку незавершённых зависимостей.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] На зафиксированном release-candidate SHA проходит 80-минутный сценарий: запрос → выбор → прогулка по реальным POI → глава/задание → «замёрз» → согласованное изменение → итог → коллекция → opt-in профиль. Координаты/replay/поле честно маркированы.
- [ ] Отдельно пройдены отказ GPS, ручной старт, screen-off Arrival, различимая ручная отметка, offline-карта/текст/аудио/прогресс, process kill/resume и идемпотентный итог.
- [ ] Полный минимум M2 из PRODUCT-SPEC/DECISIONS A01, RU/kk/EN, сюжетные задания, автоматическое первое уведомление, коллекции, следующая глава и feedback включены в accepted scope. Отсутствие функции не скрывается переименованием в v2.
- [ ] Уровни M2-TECH и FIELD-PASS разделены. При техническом PASS без поля разрешена лишь закрытая исследовательская бета 18+ с явными ограничениями районов/устройств; обещание проверенной проходимости/сопровождения отсутствует. Пилот T19 может собрать поле без циклической блокировки доступа к сборке.
- [ ] Нет известных блокирующих дефектов: потеря прогресса, ложное GPS-подтверждение, критически неверный путь/расписание, утечка данных, непреднамеренный платный вызов.
- [ ] Закрыт live-routing gate T02: законная реальная геометрия GPS start/end/return доказана. M2-TECH не принимается при скрытой подмене публичным anchor, фиктивном подходе/connector или ограничениях провайдера, несовместимых с текущей геолокацией.
- [ ] Отчёт указывает APK/hash, версии данных/контента, устройства, ограничения и все незавершённые проверки. При FAIL версия остаётся внутренней сборкой, а не принятой бетой.

## Ошибки и пограничные случаи

- Недоступна полевая проверка: M2-TECH может завершиться честно маркированной исследовательской бетой; FIELD-PASS остаётся незакрытым. Недоступный обязательный языковой/функциональный тест не засчитывается.
- Новый SHA после исправления: повторяются затронутые проверки и обязательный smoke полного пути.

## Доказательство готовности

- Подписанный checklist приёмки с фактическими reviewer и датами.
- Видео полного технического пути и APK SHA-256. Поле — только если уже проведено, не обязательное доказательство T18; обязательный FIELD-PASS относится к T19.
- Сводка Known limitations и результаты стандартов/спецификации отдельно.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
