# T22: Выпустить проверенный продукт и материалы первого трека

**Владелец:** Root + Друг  
**Blocked by:** T20 — Получить новую прогулку с учётом уже открытого; T21 — Продолжить продукт при сбоях backend и восстановить его безопасно  
**Статус:** blocked  
**Этап:** G4 — в пределах 1–3 месяцев по gates  
**Спецификация:** [PRODUCT-SPEC](../PRODUCT-SPEC.md) — US-01–38 и матрица требований первого трека; AT-01–20.  
**Решения:** [DECISIONS](../DECISIONS.md), [GLOSSARY](../GLOSSARY.md), [ARCHITECTURE](../ARCHITECTURE.md); численные нормы берутся из этих источников.  
**Оценка:** 1–2 рабочих дня; измеренный прогноз уточняется после baseline.  
**Base SHA / ветка:** назначает Root при старте; ветка codex/t22-release-and-track-demo. Сейчас кода/репозитория нет.

## Что получает пользователь

Получатель устанавливает воспроизводимую версию и видит доказательство реальной прогулки, автоматизированного сбора, RAG и ограничений; демонстрация укладывается в требования трека.

## Scope и самостоятельность

Финальная проверка/release pack, сценарии, privacy, видео и презентация 5–7 минут. Публикация во внешние магазины не следует автоматически из готовности пакета.

Исполнитель самостоятельно выбирает Implementation внутри согласованного Interface. Нормативные сущности и численные пороги берёт из PRODUCT-SPEC/GLOSSARY/ARCHITECTURE/DECISIONS. Изменения общих Interface, миграций, зависимостей/lockfile и нового обещания пользователю согласует с владельцем. Другие модули не рефакторит попутно.

## Критерии приёмки

- [ ] Есть версия, исходный SHA, APK SHA-256, версии схем/данных/контента, воспроизводимая инструкция сборки и установка на заявленных Android.
- [ ] Финальный smoke охватывает запрос, 1–3 предложения, реальный RAG с источниками, пешую выполнимость, адаптацию, GPS/ручную отметку, три языка, квест/коллекцию, offline/resume и управление профилем.
- [ ] В материалах раздельно показаны автоматический сбор/дедупликация, retrieval/генерация и детерминированные ограничения; AI-описание не выдаётся за источник факта.
- [ ] Подготовлены сценарии/ограничения, privacy-заметки, архитектура и доказательства, презентация на 5–7 минут и видео фактической работы.
- [ ] Все ограничения устройств, районов, языковой/полевой проверки, внешних сервисов и стоимости явно перечислены; симуляция не обозначается реальной прогулкой.
- [ ] Definition of Done закрыт, нет блокирующих дефектов; финальные отчёты Standards и Spec сохранены отдельно. Приватные ключи, admin capabilities и платёжные данные отсутствуют в раздаваемом пакете.
- [ ] До внешнего выпуска с обещанием проверенных районов принят FIELD-PASS T19 по EXECUTION. M2-TECH сам по себе разрешает только исследовательскую закрытую бету и не подменяет это условие.

## Ошибки и пограничные случаи

- Демо офлайн/сервис недоступен: заранее подготовлен честно обозначенный сохранённый сценарий, без подмены видео живым запуском.
- Последнее изменение после приёмки: заново зафиксировать SHA/артефакты и повторить затронутые проверки.

## Доказательство готовности

- Release manifest, APK и checksum, воспроизводимый build report.
- Финальное видео/презентация и сценарий выступления.
- Acceptance report с отдельными Standards/Spec и known limitations.

## Условия принятия

Все AC выполнены на зафиксированном SHA; независимые Standards и Spec review не имеют блокирующих замечаний; выполняется общий Definition of Done из TEAM-WORKFLOW. Сценарий/fixture/симуляция/реальная полевая проверка обозначены отдельно. Пропущенный тест или недоступный человек/устройство не объявляются PASS. Текущий файл — план, ни один checkbox не означает уже выполненную работу.
