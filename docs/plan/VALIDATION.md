# Проверка пакета планирования

Дата: 20 октября 2026. Проверяется согласованность и пригодность плана к исполнению. Приложение, APK, маршруты, реальные квоты аккаунтов и полевые результаты этой проверкой не подтверждаются.

## Что проверено

- В спецификации 38 уникальных пользовательских историй US-01–38 и 20 приёмочных сценариев AT-01–20.
- В tracker 22 задачи, 32 прямые зависимости; нет неизвестных блокировок, самозависимостей и циклов. Начать можно с T01 и T02; остальные имеют статус blocked. Владелец, статус и зависимости каждого файла совпадают с общей таблицей.
- Все US/AT представлены в ссылках задач. Есть 145 отдельных критериев приёмки; они оставлены невыполненными. Связь с AT-20 не заменяет предметную проверку каждого требования при реализации.
- Относительные файловые ссылки ведут в существующие файлы/каталоги пакета. Внешние ссылки собраны в исследовании как первичные источники; механический валидатор не проверяет их будущую доступность и содержание.
- В задачах разделены M2-TECH и FIELD-PASS. Доступ к исследовательской сборке не требует заранее законченного пилота; внешний выпуск требует реального поля.
- Версия навыков перенесена из сверенного lock. Набор skills и проверка Windows-MCP не выдаются за готовность мобильного продукта.

Машинный результат: [validation-report.json](validation-report.json). Повторить структурную проверку можно обычным Python 3: `python checks/validate_plan.py` из корня распакованного пакета. Проверка читает файлы и не запускает сервисы, установщики или продуктовые тесты.

## Независимая содержательная проверка

Три субагента проверяли продукт и его полноту, разделение задач двух Codex, архитектуру и доступные ресурсы. Главный Codex свёл результаты и проверил ключевые переходы между документами. До упаковки устранены следующие проблемы:

| Проблема | Итоговое правило |
|---|---|
| Публичная точка маршрутизации могла молча заменить реальный старт | Исходный endpoint и выбранный конец сохраняются. Реальная геометрия подхода, возврата и допустимость провайдера проверяются в T02; отсутствие решения блокирует соответствующую готовность |
| Старый офлайн-пакет мог дать ложный статус после адаптации | Ready относится к revision/hash/manifest. Новый состав проверяется заново, прерванная загрузка отображается как неполная |
| Продление истёкшей ссылки смешивалось с отменой отзыва | Обычное expiry допускает явное продление; revoke/rotate необратимы для старого URL. Аварийное восстановление БД инвалидирует прежние ссылки и требует новой публикации |
| Пилот и допуск к пилотной сборке могли зависеть друг от друга | T18 принимает M2-TECH; T19 получает полевые доказательства; внешний T22 зависит от них |
| Смешивались идентификаторы этапов и технических проверок | TEAM содержит этапы G0–G4; ARCH использует именованные проверки. Offline связан с T10, контекст — с T08 |
| Модель Codex могла выглядеть как подтверждённая модель API | Конкретный OpenAI API ID выбирается только после проверки доступности, цены и качества в аккаунте |
| Последовательные повторы не помещались в сетевой deadline | Общий бюджет времени, ограниченная параллельность и число вызовов включают повторы. Hard timeout и продуктовая цель задержки различаются |
| Различались минимумы наполнения и полевой проверки | PRODUCT-SPEC определяет продуктовый минимум; EXECUTION — обязательные полевые проверки; ранний T02 не объявляет проверенным весь город |

Проверка подтверждает устранение найденных противоречий на момент упаковки. Она не доказывает отсутствие любых будущих технических ограничений. Для них заданы измеримые ранние проверки с PASS/FAIL и допустимыми альтернативами.

## Что остаётся исполнить

T01/T02 должны доказать совместную нативную сборку, Android с погашенным экраном, допустимую офлайн-карту, три языка аудио, пригодность данных/пешего графа и доступные ресурсы без новых расходов. T03 фиксирует рабочие версии и общий контракт только после этих результатов. Дальше выполняются задачи tracker, проверки на устройствах, языковая редактура, поле и пилот.

Никакие задачи реализации не закрыты, внешние issues и платные обязательства в рамках завершения плана не созданы. Архив содержит документы, переносимый lock, проверочный скрипт и отчёт; ключи, настройки подключения и снимки чужого экрана в него не входят.

## Целостность

[manifest.json](manifest.json) содержит SHA-256 каждого файла пакета, кроме самого manifest. Проверка архива после создания сверяет эти hashes с упакованными байтами. После изменения документа manifest и отчёт проверки следует пересоздать; старый digest не подтверждает новую редакцию.
