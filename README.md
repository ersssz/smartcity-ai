# smartcity-ai

Совместный проект двух ноутбуков с Codex.

## Как работать

1. Каждый клонирует `https://github.com/ersssz/smartcity-ai.git` под своим GitHub-аккаунтом. Другу нужен доступ Collaborator.
2. Владелец работает в `codex/backend`, друг — в `codex/frontend`. Откройте локальную папку проекта в Codex и укажите свою роль.
3. Перед новой задачей выполняйте fetch и merge `origin/main` в свою ветку при чистом рабочем дереве. Между задачами сохраняйте изменения коммитом.
4. После проверки завершённой части делайте обычный push своей ветки. Фоновый интегратор на ноутбуке владельца проверяет обе опубликованные ветки каждые 10 минут и объединяет их в `main`.
5. Рабочие агенты не отправляют изменения в `main`. Фоновый процесс не переключает ветки и не меняет файлы в ваших рабочих папках.

Codex: следуй общим правилам в `AGENTS.md`. Самостоятельно делай коммиты и push только в рамках порученных задач и только своей ветки. В `main` публикует только интегратор. Никакого force push.

## Проверки перед автоматическим объединением

Приложение пока не реализовано. Пустой `.codex/integration-checks.json` разрешает только изменения документации. При выборе стека добавьте реальные команды установки зависимостей по lockfile, сборки и тестов. Каждая команда выполняется в чистом worktree и должна завершаться ненулевым кодом при ошибке.

Формат файла:

```json
{
  "checks": [
    {
      "name": "Название проверки",
      "command": "имя исполняемой команды",
      "arguments": ["аргумент"],
      "workingDirectory": "."
    }
  ]
}
```

Пример описывает формат, а не готовую проверку. Не вставляйте его без адаптации к стеку.

## Если объединение остановилось

При конфликте, ошибке проверки или запрете push в main интегратор сохраняет диагностику и сообщает владельцу. Исправьте рабочую ветку и отправьте новый коммит; он будет проверен на следующем запуске. Неизменившаяся проблемная версия повторно не обрабатывается.

Для ручной диагностики скрипт `tools/Sync-Integration.ps1` принимает `-CoordinatorPath` с путём к отдельному служебному клону, `-DryRun` для проверки без push и `-Retry` для повторения той же версии. Не используйте рабочую папку разработчика как служебный клон.

Расписание создаётся в приложении Codex на ноутбуке владельца и не переносится автоматически через Git. Для фоновой работы ноутбук должен быть включён, приложение запущено, а GitHub доступен. Отключайте автоматизацию в разделе расписаний после хакатона.
